# 교육용 COBOL 규칙 비교 결과

검증일: 2026-10-31. **비교한 3,072건에서 불일치 0건.** 직접 작성한 교육용 COBOL 프로그램 3개와 기존 finlang 규칙 3개에 같은 계약 입력을 실행했다. 전체 입력 공간의 동치, 임의 COBOL 프로그램의 호환성, 실제 은행 업무의 운영 적합성을 증명한 결과는 아니다.

## 결과

| 규칙 | 실제 양쪽 실행 | 일치 | 불일치 | 정상 금액 | 양쪽이 거절한 수신 범위 초과 | 별도 계약 입력 거절 |
|---|---:|---:|---:|---:|---:|---:|
| interest_v1 | 1,024 | 1,024 | 0 | 610 | 414 | 16 |
| fee_v1 | 1,024 | 1,024 | 0 | 1,024 | 0 | 12 |
| sum_v1 | 1,024 | 1,024 | 0 | 681 | 343 | 12 |
| 합계 | **3,072** | **3,072** | **0** | **2,315** | **757** | **40** |

일치율의 분모는 실제 양쪽에서 실행한 3,072건이다. 정상 값만 비교하지 않고 `status`, 오류 분류, 금액 문자열의 자릿수, 통화 계약, 분기를 함께 비교했다. 수신 범위 초과 757건은 양쪽이 `E_LEGACY_RANGE`로 거절한 일치 사례다. 계약 단계에서 거절한 40건은 COBOL로 보내지 않았으며 실행 일치 건수에 더하지 않았다.

독립 수작업 기준값은 이자 16개·수수료 13개·합산 25개, 총 **54개**다. 모두 두 구현이 기준값과 일치했다. 수수료는 실제 trace에서 읽은 분기를 비교했으며 하위 구간 511건·상위 구간 513건이었다. 경계 양쪽의 정산 금액이 같아도 분기가 달라진 것을 잡는다.

## 주요 경계 사례

| 입력 | 확인한 결과 |
|---|---|
| 단리: 1000000 × 0.05 × 0.5 | KRW 25000 |
| 단리: 0인 원금·이율·기간 | KRW 0 |
| 단리: HALF_UP 중간값 직전·중간·직후 | 지정한 정수 자리 반올림 |
| 단리: 999999999.99 × 1 × 10 | E_LEGACY_RANGE |
| 단리: 정산 직전 값 999999999.50 | 반올림으로 수신 범위를 넘으므로 E_LEGACY_RANGE |
| 수수료: 999999.99 / 1000000 / 1000000.01 | 금액은 모두 KRW 1000, 분기는 low / low / high |
| 수수료: 1002000 | KRW 1001 |
| 합산: USD 0.335 세 건 | 합산 후 한 번 HALF_EVEN 정산 → USD 1.00 |
| 합산: ±1.005, ±1.015, -0.005 | 양수·음수의 짝수/홀수 중간값 처리 |
| 합산: 음수 보정·상쇄·음의 0 부근 | 정확한 합산, 0.00의 음수 부호 제거 |
| 합산: ±999999999.995 부근 | 수신 경계 안의 값과 반올림 후 범위 초과 구분 |

초기값이 같다고 모든 경로가 같다는 뜻은 아니다. 특히 합산 후 정산과 개별 정산 후 합산을 섞지 않았으며, COBOL에서 중간 필드로 저장할 때 자리 손실이 생기지 않게 했다.

## 고정한 프로필과 실행 환경

[edu-packed-v1 프로필](../../testdata/cobol/profile.md)에 필드·모드·프로토콜을 고정했다. 원금과 수수료 입력은 부호 있는 정수 9자리·소수 2자리, 합산 입력은 각 정수 9자리·소수 3자리다. 단리 이율은 소수 6자리, 기간은 소수 6자리다. 모든 계산의 중간 필드는 정수 15자리·소수 14자리 PACKED-DECIMAL이며 단리의 최대 입력 소수 합 2+6+6=14를 그대로 보존한다.

단리·수수료의 수신 필드는 부호 있는 정수 9자리, 합산 수신 필드는 부호 있는 정수 9자리·소수 2자리다. `ON SIZE ERROR`를 명시했으며 자동 포화나 자리 넘침을 정상 결과로 바꾸지 않는다.

- Windows/amd64, Go 1.25.5.
- 실제 컴파일러: GnuCOBOL 3.2.0, MSYS2 UCRT64 패키지 `1~3.2-10`.
- 생성된 C를 컴파일한 도구: 기존 MSYS2 GCC 13.2.0. `cobc --version`에 표시되는 빌드 시 C 컴파일러 버전과 구분한다.
- 컴파일: `cobc -x -free -std=cobol2014 -freserved=NEAREST-EVEN -o <실행 파일> testdata/cobol/<규칙>.cob`.
- 입력은 문자열, 프로세스 실행은 `exec.CommandContext`의 직접 인수 배열을 사용한다. 쉘 명령 문자열을 조립하지 않는다.
- 규칙마다 한 번 컴파일한 뒤 1,024개 입력을 배치 실행한다. 컴파일·실행 실패, 시간 초과, 예상 밖 stderr, 누락·중복·순서가 다른 출력은 실패로 처리한다.

시드는 `20261031`이며 규칙 순서에 따라 0·1·2를 더해 별도 난수 생성기를 쓴다. 수작업 경계 앵커와 고정 시드 생성 사례를 합쳐 규칙당 서로 다른 계약 허용 입력 1,024개를 만들었다. 이 표본의 오류 비율을 실제 금융 데이터의 발생 비율로 해석하지 않는다.

## 실제로 발견한 차이와 처리

결과를 맞추기 위해 수식·정산 정책·수신 범위를 바꾸지 않았다. 실행 준비 과정에서는 다음 환경·문법 문제를 확인했다.

1. 엄격한 `cobol2014` 단어 목록은 `COMP-3` 별칭을 허용하지 않았다. 같은 저장 형식의 표준 표기 `USAGE PACKED-DECIMAL`로 바꿨으며 부호·자리·스케일은 그대로다.
2. 해당 버전의 엄격한 단어 목록은 파서가 지원하는 `NEAREST-EVEN`도 활성화하지 않았다. `-freserved=NEAREST-EVEN`을 명시해 활성화했다. 다른 반올림 모드로 대신하지 않았다.
3. 네이티브 컴파일러에 한글이 들어간 절대 소스 경로를 주면 `Illegal byte sequence`가 발생했다. 작업 디렉터리는 저장소로 두고 ASCII 상대 소스 경로를 전달해 해결했다. 원본 소스 파일을 바꾸거나 다른 사본으로 대체하지 않았다. 네이티브 도구의 임시 실행 파일 경로에도 비ASCII 문자가 있다면 ASCII 임시 디렉터리를 설정해야 할 수 있다.

따라서 이 결과의 비교 대상은 위 옵션으로 실행한 **GnuCOBOL 프로필**이다. 순수 COBOL 2014 적합성이나 IBM Enterprise COBOL의 동일 동작을 검증했다고 쓰지 않는다. GnuCOBOL의 반올림 모드와 `ON SIZE ERROR`는 [공식 가이드](https://gnucobol.sourceforge.io/HTML/gnucobpg.html#ROUNDED)를 참고했다. 사용한 패키지는 [공식 MSYS2 패키지 정보](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-gnucobol)에서 확인했다.

## 재현과 증거

GnuCOBOL과 C 도구 체인을 구성한 뒤 저장소 루트에서 실행한다. 인터프리터 런타임 자체는 Go 표준 라이브러리만 사용하며, COBOL은 비교 테스트의 별도 의존성이다.

PowerShell:

```powershell
New-Item -ItemType Directory -Force build | Out-Null
$env:FINLANG_REQUIRE_COBOL = '1'
$env:FINLANG_COMPAT_REPORT = Join-Path (Get-Location) 'build/compatibility.jsonl'
go test ./tests/compat -run TestCOBOL -count=1 -v
```

POSIX 셸에서 같은 테스트를 실행하는 명령:

```sh
FINLANG_REQUIRE_COBOL=1 FINLANG_COMPAT_REPORT="$PWD/compatibility.jsonl" go test ./tests/compat -run TestCOBOL -count=1 -v
```

이 검증은 Windows에서 실행했으며 위 POSIX 명령의 별도 Linux 실행 결과를 보고하는 것은 아니다. `COBC`로 컴파일러 경로를 지정할 수 있고, 설치 방식에 따라 DLL 검색 경로·`COB_CONFIG_DIR`·C 컴파일러 설정이 필요하다. 실제 사용한 환경 변수·컴파일 명령·파일 해시는 JSONL header에 있다. 도구 체인이 없으면 기본 테스트는 이유를 표시하고 비교를 건너뛴다. **배포 검증에서는 `FINLANG_REQUIRE_COBOL=1`로 누락을 실패 처리**했다.

- [전체 실행 JSONL](v0.3-compatibility.jsonl): header, 계약 거절 기록, 실행 입력과 양쪽 결과, 규칙별·전체 summary.
- [테스트 구현](../../tests/compat): 비교기의 값·자리·통화·분기·상태 차이 검출과 출력 스트림 검사를 포함한다.
- [구현 과정](../development/v03-compat-report.md), [COBOL 준비 기록](../development/v03-cobol-report.md).

JSONL의 소스 해시로 비교한 파일을 확인할 수 있다. 컴파일러 위치와 임시 출력 경로는 실행마다 달라질 수 있으므로 서로 다른 환경의 보고서 전체 바이트 일치를 요구하지 않는다. 입력 생성과 결과 비교 순서는 고정돼 있다.

사용성 평가는 [계획과 빈 기록지](usability.md)만 준비했으며 실제 참가자 데이터는 없다. 원래 계획의 사람 대상 사용성 완료 기준은 미충족이다. 실제 업무 규칙·운영 시스템·트랜잭션·권한·복구의 대체 가능성도 별도 검증이 필요하다.
