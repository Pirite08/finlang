# 사용 과제 평가 계획과 빈 기록지

2026-10-31. **실제 참가자 평가: 미실행.** 모집한 참가자, 관찰한 완료 시간, 실수 수, 도움 요청 수, 설명 점수는 없다. 아래 숫자는 계획의 조건과 정답 확인용 값이며 관찰 결과가 아니다. 따라서 사용성 원자료가 필요한 v0.3 완료 기준은 이 문서만으로 충족되지 않는다.

## 참가자와 진행 조건

프로그래밍 경험이 비슷한 3~5명을 모집한다. 시작 전에 Go·Python·금융 계산 경험과 각 도구 사용 경험을 기록한다. 식별자는 P01처럼 익명으로 두고 결과와 개인 연락처를 함께 저장하지 않는다. 참여를 중단한 경우 미완료 기록을 남기되 실패 시간으로 바꾸어 평균에 넣지 않는다.

같은 컴퓨터, 편집기, 글꼴 크기와 실행 안내를 제공한다. 두 언어 모두 문자열에서 정확한 십진수를 만들며, Python은 표준 `decimal`의 precision=512와 명시적 반올림 모드를 사용한다. Python의 통화 보조 함수는 미리 제공하고 수정 과제에서 제외한다. 이 보조 함수의 존재와 길이는 함께 기록한다. Python에 없는 통화 검사를 참가자가 새로 구현하도록 요구하지 않는다.

언어별 안내와 연습은 각각 5분, 각 수정 과제는 최대 8분으로 맞춘다. 양쪽에 같은 업무 설명·정답 예제·한 장짜리 문법 참고표를 준다. 외부 검색과 생성형 AI 사용 여부는 전원에게 같은 조건으로 정해 기록한다. 기본 계획은 제공한 참고표만 허용한다.

참가자가 요청하면 과제당 두 번까지 동일한 단계의 힌트를 제공한다. 첫 힌트는 수정할 규칙의 위치, 둘째는 해당 연산이나 비교의 의미를 설명한다. 완성 코드를 대신 써주지 않는다. 도움 시간도 수정 시간에 포함하고 실제 도움 문장을 기록한다. 참가자에게 도구 오류가 생기면 평가 시간과 분리하여 원인과 중단 시간을 남긴다.

홀수 순번은 DSL의 A형 다음 Python의 B형, 짝수 순번은 Python의 A형 다음 DSL의 B형으로 배정한다. A/B형은 숫자만 바꾸고 수정 동작·검사 수를 맞춘다. 참가자별로 시작 과제를 하나씩 순환하여 같은 과제가 항상 처음에 오지 않게 한다. 3명이나 5명처럼 홀수 표본이면 순서가 완전히 균형 잡히지 않았음을 결과에 명시한다.

## 같은 수정 동작을 요구하는 네 과제

각 과제는 정상 동작하는 출발 프로그램에서 시작한다. 참가자는 업무 설명대로 규칙을 바꾸고 검사용 입력을 실행한다. 아래 예상 결과는 수정 후 기준값이다.

| 과제 | A형 업무와 수정 후 검사 | B형 업무와 수정 후 검사 | 두 언어에서 바꿀 곳 |
|---|---|---|---|
| 이율 변경 | 원금 1000, 이율 0.04를 0.05로 변경. 이자=50 | 원금 2000, 이율 0.02를 0.03으로 변경. 이자=60 | DSL 숫자 리터럴 / Python `D("...")`의 이율 |
| 수수료 경계 | 100 미만이면 1, 그 밖에는 2인 규칙을 **100 이하이면 1**로 변경. 99.99→1, 100→1, 100.01→2 | 경계를 200으로 사용. 199.99→1, 200→1, 200.01→2 | `<`를 `<=`로 변경 |
| 반올림 모드 | ±2.345를 소수 2자리 HALF_EVEN에서 HALF_UP으로 변경. 2.35, -2.35 | ±4.125 사용. 4.13, -4.13 | DSL 모드 문자열 / Python 모드 상수 |
| 통화 오류 수정 | USD 10과 USD 2의 합계에서 청구 통화를 KRW로 변경. 첫 금액만 바꾸면 오류가 나므로 두 입력 통화를 일치시킨다. KRW 12, 혼합 통화는 거부 | USD 20과 USD 3으로 시작. 수정 후 KRW 23, 혼합 통화는 거부 | 두 금액의 통화 표기. 환율 계산은 하지 않음 |

출발 프로그램의 A형 핵심 부분은 다음과 같다. B형은 위 표의 원금·이율·경계·금액·반올림 입력만 바꾼다. 평가 전에 진행자가 양쪽 프로그램의 원래 결과와 수정 후 기준값을 모두 실행하여 확인하고, 실제 사용한 파일·버전·검사 입력을 보관해야 한다. 이 절차는 아직 참가자와 수행하지 않았다.

DSL:

```text
let interest = fn(principal, rate) { return principal * rate; };
let annual_rate = 0.04;
print(interest(1000, annual_rate));

let fee = fn(amount) {
    if (amount < 100) { return 1; }
    return 2;
};
print(fee(99.99));
print(fee(100));
print(fee(100.01));

print(round(2.345, 2, "HALF_EVEN"));
print(round(-2.345, 2, "HALF_EVEN"));

let first = money("USD", 10);
let second = money("USD", 2);
print(format_money(first + second, 0));
```

Python:

```python
from decimal import Decimal as D, getcontext, ROUND_HALF_EVEN, ROUND_HALF_UP

getcontext().prec = 512

# Provided scaffolding, excluded from the participant's edit task.
def money(currency, amount):
    if currency not in {"KRW", "USD"}:
        raise ValueError("unsupported currency")
    return currency, D(amount)

def add_money(left, right):
    if left[0] != right[0]:
        raise ValueError("currency mismatch")
    return left[0], left[1] + right[1]

def interest(principal, rate):
    return principal * rate

annual_rate = D("0.04")
print(interest(D("1000"), annual_rate))

def fee(amount):
    if amount < D("100"):
        return D("1")
    return D("2")

for amount in ("99.99", "100", "100.01"):
    print(fee(D(amount)))

for amount in ("2.345", "-2.345"):
    print(D(amount).quantize(D("0.01"), rounding=ROUND_HALF_EVEN))

first = money("USD", "10")
second = money("USD", "2")
currency, amount = add_money(first, second)
print(f"{currency} {amount:.0f}")
```

표시할 때 붙는 끝자리 0의 수 대신 수치와 통화를 채점한다. 예를 들어 Python의 `50.00`과 DSL의 `50`은 같은 정답으로 처리한다. 두 언어의 진단 문구가 같을 필요는 없지만, 혼합 통화가 정상 결과로 통과하면 오답이다. 통화 과제의 혼합 통화 거부 검사는 진행자가 별도 입력으로 확인한다.

## 관찰과 판정

완료는 해당 과제의 모든 검사 입력이 기대한 값 또는 오류를 내는 경우다. 시간은 업무 설명을 보여준 때부터 최종 검사 통과 또는 제한 시간 도달까지 초 단위로 잰다. 잘못된 결과 수는 참가자가 실행한 출력 중 검사를 통과하지 못한 실행 횟수로 센다. 구문 오류와 값·통화 오류를 따로 적고, 같은 실행에 여러 오류가 있어도 실행 횟수는 한 번만 센다. 도움 요청은 실제 요청 횟수를 기록하며 제공한 힌트 수와 구분한다.

과제 뒤에는 “어떤 규칙을 바꾸었고, 경계 입력에서 왜 이 결과가 나오는가”를 묻는다. 설명 점수는 0=설명하지 못함 또는 핵심 규칙을 잘못 설명함, 1=수정 위치와 결과는 맞지만 이율·포함 경계·음수 절반 처리·통화 일치 중 해당 핵심 이유를 빠뜨림, 2=수정 규칙과 해당 경계의 이유를 모두 정확히 설명함으로 정한다. 발화 요약을 점수와 함께 남긴다. 점수는 진행자의 평가이며 객관적 숙련도 점수로 확대하지 않는다.
